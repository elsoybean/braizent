# Cooklang Converter

Converts recipes from their markdown form in `./recipes/` into Cooklang `.cook` files in `./cook/`. The `.cook` files power the CookCLI server (browsing, scaling, shopping lists, pantry). The markdown stays the authoritative authoring format and is **never modified** — `.cook` is a derived cooking/shopping view that can be regenerated by re-running this skill.

## Step 1: Determine Scope
- If the user names a recipe, convert only that one.
- Otherwise, convert every eligible recipe in `./recipes/`.

## Step 2: Find Recipe Files
Use Glob to list each recipe's main file: `recipes/*/[folder-name].md` (the file whose name matches its folder). Ignore variant files (underscore suffixes such as `_precise`, `_vegetarian`) at this stage — they are handled in Step 3.

## Step 3: Check Eligibility (per recipe)
Read the main markdown file and classify it:

- **Standard recipe** — has a four-column ingredient table (`Quantity | Unit | Ingredient | Preparation`) and numbered instructions. → Convert it.
- **Quick staple** — has a `**Type:** Quick Staple` header or a `[quick-staple]` tag. These are memory aids with no quantities and cannot be expressed in Cooklang.
  - If a `_precise` variant exists in the same folder (Glob `recipes/[folder]/*_precise.md`), convert that variant instead (it has a real ingredient table).
  - If no `_precise` variant exists, **skip** the recipe and record it in the skipped list.

## Step 4: Skip Already-Converted Recipes
If `cook/[folder-name].cook` already exists, skip it by default so re-runs only add new recipes. Re-convert only if the user explicitly asks to refresh a recipe.

## Step 5: Convert Markdown to Cooklang
The output has two parts: YAML frontmatter, then the annotated body.

### 5.1 Frontmatter
Between `---` fences at the very top of the file. Include only fields that exist in the source header:

```
---
title: [from the # heading]
servings: [integer; if a range like "2-3", use the lower value]
cuisine: [from Cuisine]
course: [from Category, lowercased: "Dessert" -> dessert, "Main course" -> main]
time: [from Total Time]
source: [from URL, if present]
tags: [lowercased list, brackets stripped: [tag, tag, ...]]
---
```

### 5.2 Body
Rewrite the numbered instructions as flowing prose steps, annotating inline:

- **Ingredients:** at an ingredient's FIRST mention, write `@name{quantity%unit}` using the table (multi-word names rely on the braces). Later mentions stay plain prose — never re-declare a quantity for the same ingredient.
- **Cookware:** `#name{}` at first mention (e.g. `#large pot{}`).
- **Timers:** `~{N%minutes}` (or `~{N%hours}`) wherever a step states a time.
- **Preparation column:** fold into the instruction prose (table row "onion | diced" becomes "Dice the @onion{1}..."). Do not invent a syntax for it.
- **Units:** preserve the source's metric units exactly (`g`, `ml`, `kg`). Keep temperatures as plain text (`190°C`).
- **Ranges:** "30-45 ml" becomes a single sensible value (the midpoint).
- **No quantity / "to taste":** `@salt{}` for an unspecified amount.
- **Optional ingredients:** `@?name{...}`.
- **Distinct components** (e.g. a sauce and a base): separate with `== Section ==` headers.

### 5.3 Scaling Locks
Everything scales with servings by default. Add a `=` lock (`@salt{=3%g}`) ONLY to genuinely to-taste or fixed-amount items (finishing salt, a single packet of yeast). Do **not** lock a rub or marinade that should grow with the protein. (CookCLI may emit "unnecessary scaling lock modifier" — that warning is benign; the lock still works.)

### 5.4 Fidelity (critical)
Transcribe faithfully. Do **not** add, drop, reorder, or "improve" ingredients, quantities, techniques, or steps. The markdown is the source of truth and the `.cook` must match it. If the source is genuinely ambiguous, preserve the ambiguity rather than inventing a value.

## Step 6: Write the File
Use Write to create `cook/[folder-name].cook`. Never modify the markdown in `recipes/` or any other directory. Do not touch `cook/aisle.conf`, `cook/pantry.conf`, or the `.shopping-*` files.

## Step 7: Validate (if CookCLI is installed)
If `cook` is on the PATH, run `cook doctor` to confirm the new files parse, and report any errors. The "unnecessary scaling lock" message is a benign lint, not an error.

## Step 8: Report
Summarize the run:
- **Converted:** list of recipes written.
- **Skipped (quick-staple, no precise variant):** list.
- **Skipped (already existed):** list.
- Counts for each category.

## Worked Example
A source table row and step:

```
| 2 | whole | apples | cored |
...
1. Bake for 30 minutes, then baste with the pan juices.
```

become:

```
Core each @apples{2} ... bake ~{30%minutes}, then baste with the pan juices.
```
